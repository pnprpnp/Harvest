# 生育予測の計算・評価・運用（2026-09-27）

確定仕様は `GROWTH_REQUIREMENTS.md`、到達点は `GROWTH_REQUIREMENTS_STATUS.md`。旧説明にあった未来の平年値補完、自動採用、収穫日を適期開始日の代用とする扱いは廃止した。

対象品種はマルチリーフエアリ。株重入力は要求しない。リポジトリには実農場の記録がないため、実農場の精度向上を実証済みとはいえない。テストの合成データと、端末で蓄積する実績の評価を区別する。

## 旧方式と今回の方式

| 項目 | 旧方式 | 現在 |
|---|---|---|
| 日々の生育値 | 固定温度係数×光係数 | 旧式を初期比較基準として残し、少数の温度・光係数候補と日数方式を検証 |
| 収穫評価 | 小さい1.1倍、大きい0.9倍から目標を推定 | 小さい/並/大きいを適期期間の前/内/後という制約にする。任意の適期確認日は開始日の教師 |
| 少量データ | 件数で棟別値へ切替 | ロバストな目標推定、農場→棟→ベッド→明示位置の縮約。不足時は上位の値 |
| 部分収穫 | 通常収穫から除外・重み低下 | 位置既知ならその位置のlarge信号。旧全ベッド範囲は位置不明の弱い存在信号 |
| 気象 | 将来も過去平均等で補完 | JMAの取得済み実予報がない未来日は未予測。過去の欠測補完とは分離 |
| 更新 | 気象更新時に再学習 | 採用係数を固定して気象だけ更新。教師が変わったときに候補評価 |
| 採用 | 方式比較だけ | 時系列の方式比較、凍結世代の比較、保存した新旧予測の比較。明示承認までshadow |
| 症状 | あり/なしの曖昧な真偽値 | 不明/なし/少し/多い。旧ありは程度不明として保持 |

## 元データと保存

`records`・`plantingEvents` が栽培/収穫の元データ。`getDashboardGrowthSourceState()` が実際の苗植えイベントID、日付、対象パレットで作を照合する。収穫グループと苗植え作を別々に識別し、同じ記録の多数パレットで独立作数を水増ししない。5〜180日以外、推定苗植え、対応不明の結果は通常学習へ入れない。

適期確認・EC・特殊条件・期間付き環境・手動日数補正・途中評価は `growth-observations.js` の独立記録。入力は記録タブに置き、端末へ先に保存する。同期失敗でも記録は残し、Sheets専用表へ再送できる。更新番号による比較交換で別端末の編集と競合したら、片方を勝手に上書きしない。取消は墓石として保持する。

適期確認は苗植えイベント/日付/位置が一致する収穫だけに引き継ぐ。異なる確認日は中央値で混ぜず分割する。自動引継ぎ/手入力/引き継がないを区別する。未確認のパレットは不明のまま。収穫前確認だけを単独の学習行にする接続はまだ行わず、現在は収穫との照合後に教師へ使う。

`growthDetail.schemaVersion=3` は旧JSON欄を維持する。旧falseは確認済み陰性へ変換しない。旧サーバーの応答で新しい症状の程度・日付モードを失わない。既存LocalStorageキーやSheets本体の列を置換しない。

## 計算と環境条件

旧温度式（5〜18℃上昇、18〜24℃一定、24〜32℃下降）は検証対象の初期仮定であり、普遍的な農学定数とはみなさない。`legacy`、順序制約を使う `safe`、`calendar`、温度指数1/0.7と光指数1/0.5を比較する `adaptive` を軽量計算する。初期本番はlegacy。追加の補正は検証を通るまで採用しない。

号棟・ベッド・位置・季節の補正は独立実績数を条件に上位へ縮約する。適期開始と終了は別の境界。適期日不明の通常収穫を、開始日に置き換えない。適期期間と、日付誤差から求める参考区間も別物として返す。日数方式も未来表示は実予報期間内に制限する。

`growth-evidence.js` は記録された環境の期間・範囲・入力日時を守って付与する。後日登録した遮光等を昔の評価へ漏らさない。部分的に重なる位置情報をベッド全体へ拡張せず、その場合は信頼度を下げ理由を返す。特殊条件の除外、明示した低い学習重みも判定時点を守る。手動±1℃/光0.88・1.12は経験的な設定値、重み0.5は利用者の学習方針であり、測定から得た効果ではない。

ECの異常は明示された場合だけ扱う。湿度・ECから未検証の成長係数を生成しない。途中評価と手動日数補正は通常教師へ混ぜず、元のAI予測を保持する。これらの注釈追加だけで再学習を起こさない。

## 気象の境界

既存JMAリレー・D1を使い、Open-Meteo等への依存は追加しない。実日照時間があれば天気コードより優先するが、日射量/PARの実測と同等ではない。予報には天気からの代理指標という限界がある。

正常取得した端末キャッシュを24時間再利用する。手動更新は即時取得する。通信失敗時は保存値を使えるが、予報最終日は延長しない。元の気温が欠損している日を14/24℃等で埋めない。

未来は発表日時のある取得済み予報だけ。予報外・内部欠測の未来日は不明。平年値・気候値・後日観測で未来を埋めない。過去の欠測だけは、その時点までの観測を用いる季節中央値等で補い、推定日数と低い情報重みを返す。取得時刻を架空の発表時刻にしない。

信頼度はデータ不足/参考値/中まで。高精度の保証や架空の的中確率は表示しない。実測/予報/推定/欠測日数、予報の古さ、基準作数、特殊条件をモデルの値から説明する。

## バックテストとモデルの世代

標準は収穫3日前を原点に、最大24時点のwalk-forward評価。JMA予報が今日から最大約1週間なので旧7日前固定を改めた。保存した当時の予報がなければ未予測・未採点であり、未来の実測を代用しない。元記録・苗植え・環境変更の利用可能日時も各原点で制限する。

比較優先順は適期→徒長→ばらつき→チップバーン→サイズ→数量。数量は世代の補助係数へ固定し、上位条件をすべて満たす候補に最後の非退化確認を追加する。数量不足は非阻害で、数量改善だけの採用は認めない。実適期日が十分あれば日付MAE、それ以外はサイズの区間制約を用いる。最低16独立作、5時点、42日以上、意味のある改善、直近・季節・棟別の退化なし、時点間の安定性を確認する。適期の悪化を別指標で打ち消さない。既知品質を不明へ落として見かけの成績を上げる候補も拒否する。

`growth-learning.js` は採用中とshadowを別の不変世代で持つ。気象更新は `hydrateModel()` のみ。教師署名には学習可能になった記録だけを使い、当日結果が翌日有効になる境界も反映する。初期候補が8独立作未満なら8作到達時に新試行を作る。十分な期間/作数で不合格と分かり、さらに8作以上増えた試行も新世代に置き換えられる。採用中の係数と旧履歴は変更しない。

`growth-generation-evaluation.js` は両世代の学習完了後の原点だけで凍結係数を比較する。同じ方式で係数だけ改善した候補も評価できる。0作で開始した初期本番モデルも、この世代比較では比較基準にできる。方式別の学習バックテストでは共通の未学習期間を従来どおり除く。

本番の採用候補には、この世代比較と実際に保存した新旧予測の比較を両方要求する。方式も変える場合は方式比較も必要。採用候補の古い合格署名は教師変更後に無効。同一作の複数位置を採点から落とさず、独立作数は増やさない。本人による明示採用・採用履歴のある世代への巻戻しAPIを設け、自動採用しない。

品質は3症状の確認済み程度と気象条件の関連を縮約集計し、モデル世代内に固定保存する。未入力・旧あり程度不明は程度の誤差に採点しない。リスク開始日は天候条件の参考日であり、症状発生時刻を学習したものではない。

## 履歴、診断、復元

IndexedDBに予報、予測、元入力気象、凍結モデルを不変保存する。画面を開いていない間の予報は保存されない。通常読込みは予報の索引のみ、診断用の全気象・モデルはIDで必要時に読む。保存失敗は表示失敗とは分離し、再保存できる。

`growth-analysis.js` は保存した同じ係数・原点・予報範囲で元予測を再現し、その範囲の天候だけを後日の観測に置換した診断を行う。将来観測の置換は診断専用であり本番予測や採用ゲートに混ぜない。残差を全てモデル固有の原因と断定しない。元入力がない古い履歴は天候誤差等の限定分析とする。

復元は既存農場記録を置換しない。観測とモデルは先にメモリ上で検証し、変更前の正確な保存値を退避してからマージする。採用選択・同一IDの相違は競合として残す。履歴参照は新保存先のIDへ対応付ける。IDBの取り込み後にLocalStorageが失敗した場合、端末の観測・モデルは元のバイト列へ戻す。追記済みの不変履歴は削除せず再試行で再利用する。この跨る処理を単一DBトランザクションとは呼ばない。

移行安全保存は収穫・部分収穫・苗植え・設定・パレット対応を確認し、失敗時は直前の状態へ戻す。件数だけ同じでも値が消えていれば失敗する。復旧まで失敗した場合は失敗キーを返す。全件の自動再保存や旧記録の破壊的な書換えは実施しない。

## 未解決と確認方法

数量アダプター、画面への適期終了/手動補正/優先度/カレンダー/承認/復元の接続状態は比較表を参照。途中評価の正式教師化の有効性検証、実際の症状開始日、ハウス内の連続測定、実農場の性能確認は残る。入力負担を増やす株重や毎日の適期確認を前提としない。

`node --test tests/growth-*.test.cjs relay/test/worker.test.mjs`、`python3 tools/build_all.py --check`、ブラウザー特性テスト、IndexedDB復元テストで確認する。実農場の評価は利用端末から書き出したJSONと `tools/evaluate_growth.cjs` を使う。最新の実行件数は `GROWTH_WORK_STATUS.md` に記録する。


## 2026-09-28の追加基盤

新しい世代の `coefficients.yield` に数量係数・学習日時・学習作IDを固定する。旧世代は変更せず、係数がなければ固定priorを参考表示する。保存した新旧数量と、両世代完成後の凍結係数再現を別々に採点し、16独立作・42日以上で非退化を確認する。予測時刻から保存完了時刻までの後追い入力も混ぜない。

`growth-field-validation.js` は途中評価と後日の結果を対象パレットの重なりだけで比較する。自然な大きさ変化は誤りではなく、適期確認と選別された部分収穫も別種の観測として扱う。`growth-similarity.js` は同じ栽培日数の観測気温・日照の3期間平均と時期を比較し、位置と途中評価を参考に候補を絞る。これらは教師データや予測値を書き換えない。

`growth-calibration.js` は保存予測の実績を世代・最近・季節・号棟・信頼度別に評価する。同じ作と共有収穫評価は一つの独立群とする。区間補正は20独立作で幅を決め、その結果が確定した後の別20作・5時点・全体90日以上で検証する。時刻証跡が不足する旧データは参考集計のみ。校正提案は元予測に自動適用せず、件数だけでHighへ変更しない。

地点・号棟補正の復元は差分確認と明示選択が必要で、選択しない項目は現在設定を維持する。履歴とモデルは元地点のscopeで取り込み、地点変更は今後の気象再取得と推論だけへ反映する。設定2キー限定の安全保存と読戻しにより、容量障害や並行変更時には変更前への復旧を試みる。
